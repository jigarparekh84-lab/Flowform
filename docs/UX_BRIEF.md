# Flowform — UX brief

## Intent

Flowform is a **map-primary network / footprint design studio**. The user should spend most of their time on the canvas — placing sites, drawing lanes, branching scenarios — not hunting through a planner-style nav.

This product deliberately **diverges from Ritara’s navigation**. Ritara is APS (plan, schedule, execute). Flowform is design (shape the network, then hand off).

---

## Map-primary principles

1. **Canvas owns the viewport**  
   Network map fills the main stage. Chrome (nav, inspectors, scenario strip) is secondary and collapsible.

2. **Spatial first, tabular second**  
   Tables and forms support the map (select a node → inspect). Avoid leading with grids of facilities.

3. **Scenarios live next to the map**  
   Baseline vs what-if should be one gesture away (tabs, chips, or a slim scenario rail) — not a separate “module” that leaves the canvas.

4. **Compare without losing place**  
   Overlay or split-map compare; don’t bounce users into a report-only page unless they ask for the Brief.

5. **Greenfield is a mode, not a different app**  
   Empty map + candidate layers + demand anchors. Same canvas vocabulary as brownfield redesign.

6. **Handoff is an exit ramp**  
   Clear “ready for Ritara” moment: brief + structured export. No APS screens inside Flowform.

7. **Progressive disclosure**  
   Advanced capacity, cost, and risk controls in inspectors / drawers — not permanent left-rail overload.

---

## How we diverge from Ritara nav

| Ritara (APS-shaped) | Flowform (design-shaped) |
|---------------------|---------------------------|
| Plan / schedule / order-centric modules | Projects → **Network canvas** as home |
| Deep hierarchical side nav | Slim IA: Projects, Network, Greenfield, Scenarios, Compare, Brief, Data, Handoff |
| Execution KPIs front-and-center | Design metrics (footprint cost, service reach, scenario delta) |
| Stay in-system for planning | Explicit **Handoff** out to Ritara |
| Dense operational chrome | Map-first, chrome recedes |

Do **not** mirror Ritara’s module tree. Shared brand or token language is fine later; IA must stay distinct so users never confuse “design the network” with “run the plan.”

---

## Primary surfaces (MVP)

- **Network Canvas** — titled experience; placeholder map stage + IA stubs
- **Scenario strip** — stub for named branches
- **Inspector** — stub panel for selected node / lane
- **Handoff** — stub CTA toward Ritara brief export

---

## Success feel

Opening Flowform should feel like opening a **studio**, not a dashboard: blank or loaded map, tools at the edge, scenarios named like sketches.
